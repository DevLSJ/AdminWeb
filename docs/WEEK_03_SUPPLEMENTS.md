# 4주차 구현 전 보완

- 모든 목록 표의 헤더 오른쪽 경계를 드래그해 열 너비를 조절한다. 키보드는 경계에 Tab으로 이동한 뒤 좌우 방향키를 사용한다.
- 사용자 등록은 비밀번호 확인이 일치해야 하며, 등록·재설정 API는 8~128자와 특수문자 포함을 검증한다.
- `/api/users`, `/api/users/managed`: `name`, `phone`, `email` 부분 일치 검색을 제공한다. 필터는 AND 조건이며 이름·이메일은 대소문자를 구분하지 않고 연락처는 숫자로 비교한다. UI는 300ms 입력 대기 후 자동 검색한다.
- 개인정보는 행 무결성 검증 후 서버에서 복호화하여 비교하고 응답은 마스킹한다. 검색어와 원문을 추가 저장하지 않는다. 부분 검색은 상태 필터에 해당하는 사용자 수에 비례해 복호화 비용이 증가한다. 대규모 데이터에서는 별도 검색 인덱스 설계를 검토해야 한다.
- `GET /api/audit-logs/violations?from=YYYY-MM-DD&to=YYYY-MM-DD`: 관리자 전용. 날짜를 모두 생략하면 전체 체인을 검사한다. 응답은 `logUid`, `action`, `actor`, `recordedAt`, `detectedAt`, `violations`를 포함한다. 위반 유형은 `ROW_HMAC_MISMATCH`, `PREVIOUS_LINK_MISMATCH`, `NEXT_LINK_MISMATCH`, `CHAIN_HEAD_MISMATCH`이다. 기록 시각·탐지 시각은 실제 변조 시점을 뜻하지 않는다.
- 감사로그 CSV의 상단 안내는 항목·설명·예시로 구성된 10열 표이며 UTF-8 BOM과 수식 실행 방지를 유지한다. CSV 형식은 셀 색상·너비·병합을 저장하지 않는다.
- 수동·자동 키 갱신 후 이전 버전 암호문의 서버 복호화 요청은 `KEY_VERSION_RETIRED`로 차단한다. 버전 생략 시에도 새 키 재료로만 복호화한다. 과거 버전 메타데이터와 암호화된 키 재료는 감사 이력을 위해 보존되며, 서버 외부로 이미 반출된 키 사본에는 서버 정책을 적용할 수 없다. 이전 코드로 롤백하면 과거 버전 복호화 허용 정책도 돌아온다.
- 대시보드 바로가기와 게시글 목록, 사용자·게시글 식별자 숨김, 작성자 권한에 따른 제목 강조, 게시글 상세 타이포그래피와 첨부파일 표현을 반영했다.

컨테이너·CI/CD 설정과 DB 스키마 변경은 없다. 프런트엔드·백엔드 애플리케이션 배포가 필요하다.
